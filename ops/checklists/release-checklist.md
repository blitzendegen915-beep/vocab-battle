# リリースチェックリスト(コード変更をリリースするたびに使う)

## 原則
- **GitHub Web UIへの手動アップロードは卒業する。** 変更はgit(このClaude Codeセッション含む)で行う。
  理由: 差分が残る/1コマンドで巻き戻せる/複数ファイル同時変更でも抜け漏れしない。
- 巻き戻し方: `git revert <コミットID>` → push(壊れたら即これ)。

## リリース手順
- [ ] 変更内容を `git diff` で確認(意図しないファイルが混ざっていないか)
- [ ] JSを変更した場合、`index.html` の `app.js?v=...` のバージョン文字列を更新した
      (更新しないと生徒のブラウザに旧キャッシュが残る)
- [ ] `node ops/scripts/smoke-test.mjs` が全項目OK
- [ ] コミットメッセージは日本語で「何を・なぜ」(例: `fix: 範囲指定が保存されない問題を修正`)
- [ ] push(公開=リリース。GitHub Pagesは数分で反映)
- [ ] 本番URLで変更箇所を1回実際に操作して確認
- [ ] GAS連携に触れた変更なら「共有単語を読み込む」「ランキング更新」も本番で確認

## GAS側を変更した場合(事故多発ポイント)
- [ ] デプロイは「**デプロイを管理 → 編集 → 新バージョン**」で行った
      (「新しいデプロイ」を作るとURLが変わり、全端末で接続が切れる。OLD_GAS_URLSの二の舞)
- [ ] URLが変わってしまった場合のみ: app.js の DEFAULT_GAS_URL を更新し、旧URLを OLD_GAS_URLS に追加
