# 業務マップ(英単語バトルレート運用)

対象: 英単語バトルレート(静的フロント on GitHub + GAS/スプレッドシート バックエンド)
オーナーの目的: **収益化**。運用作業は可能な限りAIに任せ、人間は判断だけする。

## 1. 業務の棚卸し

## 2. 人間がやるべき判断 vs AIに任せられる作業

**人間(オーナー)がやるべき判断:**
- シーズンをいつ切り替えるか、シーズン名
- 荒らし対応の最終判断(除外するか)
- 収益化の方針決定(広告 or スポンサー or B2B)、広告アカウント申請、契約、課金操作
- プライバシーポリシー等の公開承認

**AI/スクリプトに任せられる作業:**
- シーズン切替のコード書換(→ `ops/scripts/switch-season.mjs`)
- 単語データの検証・整形(→ `ops/scripts/validate-words.mjs`)
- リリース前の動作確認(→ `ops/scripts/smoke-test.mjs`)
- 単語リストの生成(→ `ops/prompts/word-list-generator.md`)
- 営業文・規約文の下書き(→ `ops/monetization/`)
- コード修正・コミット・push(→ Claude Codeセッション)

## 3. 一番大きいボトルネック

**リリースフローそのもの。** 「コード修正 → Web UIで手動アップロード → 本番で目視確認」は、
①ミスに気づく仕組みがない ②ロールバックできない ③シーズン切替のような複数ファイル同時変更で事故りやすい。
ここにスクリプト+チェックリスト+スモークテストを入れると、以降の全作業が速く・安全になる。
