# QAスモークテスト Skill

## 前提

`ops/scripts/smoke-test.mjs` が必要(workflow-automation-strategyブランチ由来)。現在のブランチに無ければ、そのブランチから取り込むかユーザーに確認する。

## 手順

1. 実行: `node ops/scripts/smoke-test.mjs`
2. 全OKなら「リリース可」。NGがあれば:
   - NG項目と原因(コンソールのエラー内容)を特定する
   - 直近の変更(`git diff` / `git log -3`)と突き合わせて原因箇所を推定・修正し、再実行する
   - 直せない場合は「リリース中止」を明言し、原因の調査結果を報告する
3. 合格後の案内: 「GAS連携(共有単語読み込み・ランキング)はテスト対象外なので、push後に本番URLで『共有単語を読み込む』『ランキング更新』を1回ずつ手動確認してください」

## 報告フォーマット

```
スモークテスト: 合格 (N/N) → リリース可
※GAS連携は本番URLで手動確認が必要(上記2項目)
```
NG時は「不合格 (M/N)」+ NG項目・原因・対処(修正済み/リリース中止)を続ける。

## テストが検証していること / いないこと

- ✅ ページ起動、UI要素の存在、サンプル単語読込、モード切替、JSエラーゼロ(オフライン相当)
- ❌ GAS通信、ランキング、戦闘力計算の正しさ、実機のスマホ表示
